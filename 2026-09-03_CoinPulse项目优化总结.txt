CoinPulse 项目优化工作记录
日期：2026-09-03

一、今日总体方向

本次按照“暂不接入订单流、先利用 GitHub Actions 做持续监控和数据积累”的方向，对项目进行了两批优化。

本次工作的重点不是立即改变海龟策略参数，而是提高回测真实性、建立影子交易记录，并让 GitHub Actions 自动收集后续验证策略所需的数据。

当前结论：CoinPulse 暂时不需要租云服务器，也可以继续进行策略优化、回测优化和实盘信号观察。

二、已完成的优化

1. 回测增加交易成本模型

修改文件：backtest_turtle.py

新增内容：

- 手续费可通过 --fee-rate 配置，默认 0.1%。
- 滑点可通过 --slippage 配置，默认 0.05%。
- 多头和空头分别使用不利方向的滑点。
- 手续费按照成交额单边计算。
- 回测结果记录 ending_equity、收益率、最大连续亏损和是否仍有未平仓仓位。
- 回测命令支持调整初始资金、历史K线数量、币种、并发数和输出文件。

2. 修正回测成交时点

现在的回测逻辑是：

- 当前K线收盘后确认海龟突破信号。
- 下一根K线开盘执行假想成交。
- 之后再根据盘中最高价和最低价判断加仓、止损或通道退出。

这样可以避免使用确认信号的收盘价直接成交造成的过度乐观结果。

3. 增加样本内和样本外回测

backtest_turtle.py 新增 --test-ratio 参数，默认将最近30%的历史数据作为样本外区间，同时输出：

- full：全样本结果。
- in_sample：样本内结果。
- out_of_sample：样本外结果。

报告还会对各币种进行汇总，展示交易胜率、平均币种收益、最差币种回撤和平均最大连续亏损。

注意：当前汇总是各币种结果的统计汇总，不等同于多币种组合资金曲线。

4. 建立影子信号记录

修改文件：signal_watch.py

每次产生新的海龟或其他策略信号时，将结构化信息写入 signal_records.json，包括：

- 币种和周期。
- 多空方向。
- 信号确认时间和K线时间。
- 突破触发价。
- 策略类型、海龟系统、N值和数据提供方。
- 策略版本标识。
- 当前记录状态。

记录最多保留最近500条，避免仓库状态文件无限增长。

5. 增加24小时和48小时信号表现追踪

新增文件：track_signals.py

影子追踪默认按照“信号确认后下一根K线开盘价”作为假想成交价，分别计算信号后24小时和48小时的：

- MFE：最大有利波动。
- MAE：最大不利波动。
- 观察窗口最终收益率。
- WIN、LOSS 或 FLAT 结果。
- 实际使用的数据源。

汇总结果写入 signal_tracking_stats.json，并按整体和币种分别统计观察数量、胜率和平均收益。

该功能只用于研究和评估，不会自动下单，也不会改变生产策略的入场条件。

6. GitHub Actions 增加自动追踪

修改文件：.github/workflows/signal-monitor.yml

现有监控流程继续每5分钟运行：

- 拉取行情。
- 按当前海龟规则扫描。
- 发现新信号时推送通知。
- 保存信号状态。
- 记录影子信号。
- 更新已到观察期限的24小时和48小时结果。

新增文件：.github/workflows/turtle-backtest.yml

新增每周海龟回测流程，默认使用：

- 最近2500根4小时K线。
- 0.1%手续费。
- 0.05%滑点。
- 最近30%数据作为样本外测试。

该流程只生成回测报告，不会自动调参，也不会自动修改生产配置。

7. GitHub Actions 状态文件提交范围修正

工作流现在会根据文件是否存在，选择性提交：

- signal_watch.state.json
- signal_records.json
- signal_tracking_stats.json
- trade_stats.json

避免首次运行时因某个记录文件尚未生成而导致任务失败。

8. --once 模式补充交易结算

signal_watch.py 的 --once 模式现在在扫描和登记新信号后，也会结算已经满足条件的未平仓影子交易，使 GitHub Actions 的定时运行能够持续更新交易状态。

四、当前策略状态

当前仍然保持以下原则：

- 暂不接入订单流。
- ADX 不作为默认硬性过滤条件。
- 成交量和ATR保护继续保持可配置。
- 不自动下单。
- 不把回测收益当作未来收益承诺。
- 先积累真实信号记录，再决定是否修改策略。

订单流服务 orderflow/ 目录没有被删除。它仍然是可选的本地增强功能，但当前 GitHub Actions 监控不依赖它。

五、后续优化方向

第一阶段：观察数据质量（建议先运行数周）

1. 确认 GitHub Actions 每5分钟运行稳定，推送没有重复或漏发。
2. 检查 signal_records.json 是否正确保存信号。
3. 检查24小时和48小时观察窗口是否按预期完成。
4. 观察不同币种、不同方向和不同市场阶段的表现。
5. 重点记录假突破、连续亏损、MAE、MFE和最大回撤。

第二阶段：完善回测真实性

1. 明确同一根K线同时触发止损和通道退出时的处理规则。
2. 进一步模拟加仓手续费、滑点和资金占用。
3. 加入历史资金费率，但必须使用实际资金费率时间戳，不能简单固定假设结算时间。
4. 增加多币种组合资金曲线和组合最大回撤计算。
5. 对缺失K线、交易所数据源切换和异常行情进行数据质量标记。

第三阶段：验证参数稳定性

1. 比较海龟S1和S2。
2. 测试不同突破缓冲，例如0、0.05N、0.1N和0.2N。
3. 测试不同ATR止损倍数和加仓间距。
4. 测试成交量和ATR过滤器的独立效果。
5. 使用滚动样本外回测，而不是只进行一次固定切分。
6. 只有当参数在多个币种和多个市场阶段均表现稳定时，才考虑调整默认值。

第四阶段：再考虑增强数据

1. 先把OI、资金费率和相对强弱数据作为记录字段，不直接影响入场。
2. 对增强数据进行缺失率、延迟和可重复性检查。
3. 等积累足够样本后，再进行独立的因子效果分析。
4. 只有证据充分时，才将某个因子改成评分项或过滤项。
5. 订单流仍然作为后期增强方向，不应在样本不足时直接参与实盘决策。

六、当前最重要的判断标准

后续不要只看胜率，应综合观察：

- 样本外平均收益是否为正。
- 样本外最大回撤是否可接受。
- Profit Factor 是否稳定。
- 连续亏损是否在可承受范围内。
- 不同币种之间是否过度依赖少数赢家。
- 手续费和滑点增加后策略是否仍然成立。
- 参数轻微变化后结果是否明显崩溃。

最终建议：先让 GitHub Actions 持续运行并积累数周信号，再根据实际记录决定下一轮策略改动。目前不建议租服务器、不建议接入CoinGlass付费数据，也不建议立即启用多因子评分。

七、Gemini 后期优化建议复审

今天对 Gemini 提供的后期优化建议进行了复审。总体判断是：建议中关于回测严谨性、组合风险和滚动样本外验证的方向可以借鉴，但需要结合当前项目的低频海龟策略和现有代码状态进行调整。

1. 已确认可以采用的建议

- 同一根K线同时触发多个条件时采用悲观处理。当前回测和交易跟踪逻辑已经先判断止损，再判断通道退出，确认没有退出后才处理加仓，基本符合最悲观原则。
- 后续增加多币种组合资金曲线。当前逐币种回测不能反映多个币种同时持仓时的总资金风险，这项工作列为下一阶段重点。
- 后续升级为滚动样本外回测。当前已经有固定比例的样本内/样本外切分，后续再扩展为多个时间窗口滚动验证。
- 继续克制使用付费增强数据。OI、资金费率和多空比可以先作为辅助记录，不直接改变海龟入场规则。

2. 需要修正后采用的建议

- “两到四周积累50～100条样本”不适合当前4小时海龟S2策略。此前约13.8个月、12个币种的历史回测只有38笔交易，因此短期内不可能稳定获得这么多完整样本。调整为至少积累30～50个已完成的24/48小时观察窗口，或持续运行2～3个月，以较晚达到的条件为准。
- 滚动样本外回测不能反复用样本外结果调参。当前策略不是机器学习模型，应区分开发区间、验证区间和最终样本外测试区间，避免把测试数据间接用于过拟合。
- OI、资金费率和多空比接入前需要核对官方接口路径、历史数据范围、请求限制、时间粒度和数据缺失处理，不能仅凭接口名称直接开发。

3. 暂不采用的建议

- 暂不删除 orderflow/ 目录。订单流仍作为可选本地增强功能保留，当前 GitHub Actions 监控不依赖它。
- 暂不立即接入 CoinGlass 付费 API。价格、套餐和权限需以官方当前信息为准，而且现阶段样本不足，付费数据不能解决策略验证不足的问题。
- 暂不立即启用多因子评分或让增强数据影响实盘入场。

八、明日优化优先级

1. 在回测中实现真实的多币种组合资金池和组合权益曲线。
2. 增加总风险、同方向风险和同时持仓数量限制，避免多个币种同时触发时风险叠加。
3. 补充同一根K线同时触发止损、退出和加仓的专项测试。
4. 规划更长历史数据的拉取和缓存，当前2500根4小时K线不足以支撑完整滚动样本外验证。
5. 在更长数据基础上实现滚动窗口样本外回测。

明日工作的验收标准：组合回测不改变现有单币种基线逻辑；报告能区分单币种结果与组合结果；同时输出组合收益、最大回撤、最大连续亏损、总交易数和样本外表现；所有现有测试继续通过。
