CoinPulse 项目优化工作记录
日期：2026-09-04

一、今日工作结论

今天继续按照《CoinPulse 项目总体优化大纲》推进项目。总体原则没有改变：先提高数据、执行模型和风险统计的可信度，再讨论参数变化或新增策略；当前仍然只做信号和影子交易，不自动下单，不接入订单流作为生产入场条件。

二、已完成的代码优化

1. 修正海龟推送文案

- 推送标题去掉重复的“海龟突破”，例如改为“CoinPulse BNBUSDT 海龟突破做多”。
- 将“入场点位”改为“突破触发价”，避免把通道突破价误认为实际成交价。
- 增加“影子成交：下一根4h K线开盘价（实际成交价以开盘行情为准）”提示。
- 保留结构化交易字段，兼容交易登记和历史数据解析。

2. 增强回测成交真实性

- 增加跳空处理：如果开盘价已经越过止损或加仓触发价，按更差的开盘价成交，避免假设市场在跳过的价格上仍有流动性。
- 同一根K线继续按照止损、通道退出、加仓的顺序处理。
- 回测结束时对未平仓仓位按最后收盘价、手续费和不利滑点强制平仓。
- 报告同时保留未平仓标记权益，并记录截止时是否存在未平仓仓位，避免混淆两种口径。
- 高周期日线数据长度会随4小时历史数据长度扩展，为后续3～5年回测保留足够EMA200预热数据。

3. 增加信号长期归档

- 新增 signal_archive.py。
- signal_records.json 活跃记录仍最多保留500条。
- 被移除的旧记录会按信号月份保存到 signal_archive/signals-YYYY-MM.json。
- 归档使用信号ID去重，并采用原子写入，降低GitHub Actions中断造成文件损坏或重复归档的风险。
- GitHub Actions 会提交 signal_archive 目录。

4. 增加多币种组合回测

- 在单币种回测之外增加统一资金池的组合回测。
- 输出组合收益、组合权益曲线、组合最大回撤、交易数和胜率。
- 支持单币种单位数、总单位数和同方向单位数限制。
- 同一时点多个信号按币种字母顺序确定性处理。
- 组合回测使用 production_default 变体，单币种各变体结果仍单独保留。
- 回测报告将单币种结果与组合结果分开，避免把各币种统计平均值误认为组合收益。

5. 修正命令行和测试

- 修复 backtest_turtle.py --help 因帮助文本百分号导致的 Argparse 异常。
- 新增跳空触发价测试、信号归档幂等测试、组合容量测试、空组合回测测试和推送文案测试。
- 当前 Python 单元测试共18项，全部通过。
- Python 编译检查通过。
- git diff --check 通过。
- 未运行联网全量回测，因此今天没有产生新的收益结论。

三、当前项目状态

- GitHub Actions 继续每5分钟监控和推送。
- 当前主要策略仍为4小时海龟S2。
- 当前默认仍使用已收盘K线、高周期EMA200、0.1N突破缓冲、成交量和ATR保护，ADX保持可选。
- 当前仍不自动下单，不接入订单流作为默认决策，不接入CoinGlass付费数据。
- Server酱推送已经实际收到，今天确认推送内容可读且核心N值、止损和加仓位计算一致。
- 影子信号24小时/48小时观察继续作为信号质量证据，不等同于完整海龟策略交易结果。

四、后期优化优先级

P0：统一影子交易口径

- 当前 signal_records 的影子观察按下一根K线开盘价计算，但 signal_watch.py 的实时海龟交易登记仍可能把突破触发价作为建仓价。
- 后续应统一为下一根K线开盘价，并记录实际影子成交时间、成交价、手续费、滑点、加仓和退出。
- 每条记录保存完整参数快照，包括S1/S2、突破缓冲、高周期EMA、过滤器、风险比例、手续费、滑点、数据源和策略版本。
- 统一 trade_stats、signal_tracking_stats 和回测报告的执行模型。

P1：补全组合风控和组合报告

- 在组合回测中复用实时监控的强相关组、弱相关组限制。
- 记录最大同时持仓单位、最大同方向单位、最大连续亏损和被风险限制拒绝的信号。
- 明确现货与永续合约的交易标的。若使用永续合约，再研究保证金、资金费率、杠杆和强平风险。
- 增加组合回测的同时信号、同根K线止损和期末平仓专项测试。

P2：建立3～5年可复现历史数据集

- 缓存4小时和日线历史数据，记录交易所、市场类型、时间范围、下载时间、数据源、缺失K线、异常K线和文件哈希。
- 数据源切换必须在报告中显式标记。
- 历史数据扩展后先检查时间连续性、重复K线、异常高低价和日线EMA200预热长度。

P3：完成滚动样本外验证

- 区分开发区间、验证区间和最终测试区间。
- 使用固定滚动窗口，例如12个月开发、3个月验证，逐段向前滚动。
- 每个窗口输出组合收益、最大回撤、Profit Factor、交易数、连续亏损、币种依赖和成本敏感性。
- 最终样本外区间冻结，不能反复用于调参。
- 每次实验保存参数、数据版本、执行模型、报告和代码版本，保证可比较、可回滚。

P4：增强监控可观测性

- 新增监控健康记录，包含最近扫描时间、K线最新时间、数据源、失败次数、推送结果和状态文件写入结果。
- 对重复信号、漏数据、数据延迟、推送失败和GitHub Actions失败增加可见告警。
- 持续观察1～3个月的数据质量，积累至少30～50个已完成的24/48小时观察窗口，或以持续运行2～3个月为最低观察期，以较晚条件为准。

五、暂不执行的事项

- 暂不修改海龟生产参数。
- 暂不直接让OI、资金费率、多空比或订单流影响入场。
- 暂不接入CoinGlass付费API。
- 暂不使用Pandas TA替换现有指标实现，以免改变计算口径。
- 暂不引入CCXT、QuantStats或Streamlit作为当前主线依赖；待组合权益曲线和历史数据稳定后再评估。
- 暂不租用服务器，GitHub Actions 继续承担低频监控和影子记录。

六、统一验收原则

后续每次优化都要回答：是否改变生产策略基线；是否引入未来数据泄漏；是否计入手续费和滑点；是否有专项测试；是否能在样本外复现；是否改善收益、回撤或风险；是否增加不必要复杂度；是否保留参数、数据区间和报告以便回滚比较。

最终原则：先统一执行口径，再完成组合风险和长历史验证，最后才讨论策略参数与互补策略。一次只引入一个主要改动，任何结论都必须能够解释、复现和回滚。
